# Webric Ultra Auth

قالب فارسی و راست‌چین برای ورود، ثبت‌نام، بازیابی رمز و پنل تنظیمات ظاهری، با طراحی شیشه‌ای، تم روشن/تاریک و اعتبارسنجی فارسی.

> **مهم:** این قالب یک **رابط کاربری** است. بدون بک‌اند امن، هیچ ورود، ثبت‌نام یا تغییر رمز واقعی انجام نمی‌شود و هیچ احراز هویتی تضمین نمی‌شود. فرم‌ها در حالت نمایشی، فقط اعتبارسنجی سمت کاربر را اجرا کرده و صریحاً اعلام می‌کنند که چیزی ارسال نشده است.

## امکانات

- صفحات: `index.html` (معرفی)، `login.html`، `register.html`، `reset-password.html`، `verify-code.html`، `set-password.html`، `admin.html` (پنل تنظیمات)، `demo.html` (نمونه‌ها).
- ورود با ایمیل یا موبایل، نمایش/مخفی‌سازی رمز، «مرا به خاطر بسپار» با توضیح، وضعیت‌های دکمه (عادی، در حال پردازش، موفق، ناموفق) و مکث ضد کلیک تکراری.
- ثبت‌نام با فیلدهای فعال/غیرفعال و ترتیب قابل تنظیم، نشانگر قدرت رمز، تاریخ شمسی و کد ملی با بررسی رقم کنترل.
- بازیابی رمز در چهار مرحله با نوار پیشرفت.
- پنل تنظیمات: رنگ، شیشه، سایه، فونت، چیدمان، هاله‌ها، متن‌ها، قوانین ثبت‌نام، روش‌های احراز هویت، قوانین رمز، پیش‌نمایش زنده (دسکتاپ/تبلت/موبایل)، ورود و خروج JSON، بازنشانی.
- تم روشن و تاریک واقعی، تنظیم `prefers-reduced-motion`، ناوبری با صفحه‌کلید و سازگار با RTL.

## نصب و اجرا

1. پوشه را از فایل ZIP خارج کنید.
2. فایل `index.html` را در مرورگر باز کنید؛ همه‌چیز بدون سرور هم کار می‌کند.
3. برای تست دقیق‌تر، یک سرور ساده کنار پوشه اجرا کنید، مثلاً `python -m http.server 8080`، و به `http://localhost:8080` بروید.

## انتشار روی GitHub Pages

1. مخزن جدید بسازید و همه فایل‌های این پوشه را (نه خود پوشه) در ریشه مخزن قرار دهید.
2. Settings → Pages → Source را روی `Deploy from a branch` بگذارید و شاخه `main` و پوشه `/ (root)` را انتخاب کنید.
3. تمام مسیرها نسبی‌اند، بنابراین آدرس `https://<user>.github.io/<repo>/` بدون تغییر کار می‌کند.
4. **پنل `admin.html` را پیش از انتشار عمومی حذف یا محدود کنید**؛ در GitHub Pages امکان احراز هویت سمت سرور نیست.

## سفارشی‌سازی

- **تنظیمات بصری و متنی:** در `admin.html` تغییر دهید. تنظیمات در LocalStorage همین مرورگر ذخیره می‌شود و فقط شامل مقادیر غیرحساس است.
- **مقادیر پیش‌فرض:** در `js/config.js` (`Webric.DEFAULTS`) تعریف شده‌اند.
- **قوانین ثبت‌نام:** لیست `Webric.REGISTER_FIELDS` را ببینید؛ فیلد `password` قفل است.
- **فونت Peyda:** اگر مجوز دارید، فایل‌های آن را در `fonts/peyda/` قرار دهید و خط `url()` را در `fonts/fonts.css` فعال کنید. در غیر این صورت Vazirmatn استفاده می‌شود.
- **برند:** نام، شعار و نشان در بخش «ظاهر و برند» پنل.

## اتصال به بک‌اند

1. در بخش «پیشرفته»، آدرس `https://` سرور خود را وارد کنید (در توسعه، `http://localhost` مجاز است).
2. مسیرهای endpoint را مطابق API خود تنظیم کنید. ساختار درخواست‌ها در `js/api.js` و `js/auth-ui.js` است.
3. سرور باید این موارد را **حتماً** انجام دهد: اعتبارسنجی کامل ورودی‌ها، هش امن رمز (مثل Argon2 یا bcrypt)، محدودیت تلاش و نرخ درخواست، کوکی نشست `HttpOnly; Secure; SameSite`، و پاسخ یکسان برای شناسه‌های موجود و ناموجود در بازیابی.
4. `GET /health` باید JSON با فهرست `methods` برگرداند (مثلاً `["password","sms_otp"]`) تا وضعیت «متصل» نمایش داده شود.
5. برای OAuth، آدرس `authorizeUrl` را از ارائه‌دهنده بگیرید؛ کلید کلاینت هرگز در فایل‌های عمومی قرار نگیرد.

## محدودیت‌ها

- هیچ رمز، توکن یا کلید API در مرورگر ذخیره یا ارسال نمی‌شود، اما **هیچ احراز هویت واقعی در حالت نمایشی وجود ندارد**.
- `admin.html` بدون بک‌اند هیچ محافظتی ندارد. هر کسی که آدرس را داشته باشد می‌تواند ظاهر فرم‌ها را در مرورگر خودش تغییر دهد، ولی این تغییرات روی سرور یا کاربران دیگر اثری ندارد.
- تنظیمات ذخیره‌شده فقط در همان مرورگر است.
- محدودیت تلاش، OTP پیامکی، تأیید ایمیل، ورود اجتماعی و بازیابی واقعی به بک‌اند و سرویس بیرونی نیاز دارند.
- Peyda فونت تجاری است و در بسته قرار داده نشده است.
